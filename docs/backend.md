# Generation and isolated build contract

The Next server validates requests, calls a modular provider, validates its source file list, and submits it to an independently operated build service. It never writes generated files to disk, executes Java, installs Gradle, or runs generated build scripts. `src/lib/types.ts` defines the provider/build interfaces. All configuration is read on the server. Neither provider nor build-service credentials enter browser responses.

`POST /api/generate` accepts `{prompt,version,modelId,artifactType,target,project?:{name,files}}`. The `artifactType` and `target` fields default to `plugin` and `paper` for old clients. Valid pairs are `plugin/paper|folia|purpur|spigot|bukkit|sponge|velocity|bungeecord`, `mod/fabric|quilt|forge|neoforge`, `resource_pack/vanilla`, and `shader_pack/iris|optifine`. `GET /api/generate` returns the server-owned artifact catalog for UI selectors, including labels, current output capability, and limitations; its targets are the ones the dashboard offers. `modelId` must be in the server-owned model catalog and its provider must be configured. The optional complete project supports follow-up edits within the same artifact type and target. The model also returns a short `message` for the user, which may use the workspace commands in `src/lib/chat-commands.ts` (such as `/reference <file>`, `/command`, `/warning` or `/next`); the workspace turns each one into a link, chip or button. The build worker receives only `name` and `files`. Plugins and mods accept every version their platform published, as listed in `src/lib/platforms.ts` (Velocity and BungeeCord use their API versions), and an unsupported pair is rejected with the reason. Packs accept any Minecraft release; resource packs need 1.6.1 or newer.

Each artifact type has a server-owned expert playbook and task-specific skills. These are specialized instructions, schemas, and validators supplied to the selected model; they do not fine-tune or train the model weights. Generated source must pass the selected artifact validator before it is returned. Requests are limited to 200 KB; generated source to 150 KB, 30 files, 40,000 characters per file. Traversal, absolute paths, case-insensitive collisions, arbitrary build scripts, dependencies, and binary payloads are blocked.

Paper plugins use the isolated build-service adapter to produce a JAR. Mods use that adapter only when it is backed by a secure worker with a server-owned template for the selected loader; this repository includes a Paper template only. Resource packs and shader packs are packaged locally as installable ZIPs after validation. Resource-pack metadata is normalized for 1.21.x releases, and other releases keep the generated `pack_format`, but textures and other binary assets are not generated. Shader ZIPs are not GLSL-compiled or GPU-tested. Plugin and mod outputs permit Java plus the platform's descriptor, config.yml, pack.mcmeta, mixin configs and language files, and mods may add README.md; resource packs require pack.mcmeta and namespaced text assets; shader packs require GLSL vertex and fragment stages.

## Modes

- Development defaults to `AI_PROVIDER=mock`, a deterministic source example implementing exactly the zombie Speed II / ten-second prompt. Other requests and follow-up edits are rejected with a clear message. The fixture does not interpret arbitrary natural language. It has not been compiled by this app.
- `OPENAI_API_KEY` enables the server-side OpenAI Responses API model choices. `ANTHROPIC_API_KEY` enables the Anthropic Messages API choices. `GEMINI_API_KEY` enables Gemini Interactions API choices. The server selects only IDs from `src/lib/models.ts`; credentials and provider endpoints never come from the request. `OPENAI_BASE_URL`, `ANTHROPIC_BASE_URL`, and `GEMINI_BASE_URL` are trusted HTTPS endpoints (HTTP loopback only in development).
- `AI_PROVIDER=openai-compatible` with `AI_API_KEY`, `AI_MODEL`, and `AI_BASE_URL` remains supported for earlier Chat Completions setups. In that mode the selected OpenAI catalog ID is sent to the configured compatible endpoint.
- Without `BUILD_SERVICE_URL`, development returns an explicit source preview for plugin JARs and mod JARs. Resource and shader ZIPs do not need a compiler service. No mock compilation or fake JAR download exists.
- Production disables mock generation. Plugin and mod compilation require a build-service URL and token; resource and shader ZIP packaging runs in the application process over bounded, validated text files.

## Build service protocol

Configure `BUILD_SERVICE_URL` as the exact trusted HTTPS POST endpoint and `BUILD_SERVICE_TOKEN` as a secret bearer token. HTTP loopback is allowed only outside production. Redirects are rejected. Environment URLs are administrator-controlled and must never come from a user request; protect them from untrusted configuration changes and enforce network egress allowlists at deployment.

Request JSON:

```json
{"schemaVersion":1,"platform":"paper","javaVersion":21,"minecraftVersion":"1.21.4","project":{"name":"ZombieSprint","files":[{"path":"src/main/java/dev/example/Main.java","content":"..."},{"path":"src/main/resources/plugin.yml","content":"..."}]}}
```

Every other plugin and every mod uses protocol `schemaVersion` `2`: `{"schemaVersion":2,"artifactType":"mod","platform":"fabric","family":"fabric","javaVersion":21,"mappings":"mojang","minecraftVersion":"1.21.11","project":{...}}`. `family` groups platforms that share a descriptor format (`bukkit`, `sponge`, `velocity`, `bungeecord`, `fabric`, `quilt`, `forge`, `neoforge`), `javaVersion` is the Java release that platform and version need, and `mappings` is `mojang`, `yarn`, `mcp` or `none`. Velocity and BungeeCord send `apiVersion` instead of `minecraftVersion`. The worker must select an immutable, server-owned template for that exact platform and version and return a JAR. The current repository does not include those templates or an actual sandbox worker; the app deliberately returns a source preview when no loader-capable worker is connected. The worker must reject unsupported combinations before compiling. Paper plugin requests remain on protocol version 1 for compatibility with the existing Paper worker.

Response JSON: `{ "success": false, "logs": ["Compiler diagnostic"] }` or `{ "success": true, "logs": ["BUILD SUCCESSFUL"], "artifactBase64": "UEsDB..." }`. At most 100 log lines of 2,000 characters each; decoded artifact at most 5 MB. The app checks ZIP local-header bytes as a format sanity check, not proof of trustworthy contents or runtime correctness. The service must ensure the returned artifact is the actual generated plugin, not dependencies or an arbitrary archive. Do not put credentials, environment variables or host paths in diagnostics.

The service is an interface, **not an included sandbox implementation**. Before connecting one, it must authenticate requests; repeat input validation; create a disposable non-root sandbox for every build; use an immutable server-owned Gradle template targeting the requested Java version and platform API; never accept user Gradle scripts; deny Docker socket and host filesystem access; mount no host secrets; enforce CPU, memory, disk, PID and wall-time limits; and deny outbound networking except a controlled read-only dependency mirror. Prefer preloaded dependency caches and fully disabled egress during compilation. Java annotation processors and Gradle execution must remain within the sandbox. Destroy the sandbox after collecting bounded compiler diagnostics and the JAR. Run downloaded plugins only on a disposable test server. Do not place a Docker daemon or execute generated Java in the Next process.

The request timeout is 120 seconds per build. Local provider calls allow 10 minutes; hosted calls allow 90 seconds for OpenAI and Anthropic, 180 seconds for Gemini, or 240 seconds for shaders. A separate 15-second limit applies to receiving JSON bodies, including incoming requests. A failed compilation triggers at most **three repairs** (four total build attempts), each sending current source and diagnostics to the provider. Network/service failures do not trigger repairs. Compilation is not behavior verification.

## MVP operational limits

Artifacts are process-memory only, expire after 30 minutes and are evicted after 20 stored artifacts. Restarts, multiple instances, and serverless process changes may invalidate downloads. Browser history is separate; it is not persistent server storage. Download IDs are random UUID bearer capabilities; no accounts or ownership checks are implemented. Keep this MVP private/local. Before public deployment add authentication and artifact authorization, durable object storage, a job queue, per-account quotas/rate limits, abuse controls, and a provisioned sandbox build service. The current two-job concurrency guard is process-local and not a public abuse-control system. A request may last several minutes; hosting needs long request support or the future durable queue.

Verbose compiler and pipeline logs are returned in the project. Provider service response bodies are deliberately excluded from errors so secrets accidentally echoed by providers are not exposed. The administrator must configure the build service to return sanitized logs.
